Install the root certificate of the computer running the dev server and this device opens it over https without a warning. Service workers, push, install and the other secure-context APIs need it.

Once installed, the fingerprint the device shows must match the one the dev server prints in its terminal: this page travels over plain http, so the network could swap the file.

Android (this device)
  1. Tap Download the root certificate. Opening the file only says CA certificates must be installed from Settings: that is expected.
  2. In Settings, search for CA certificate. Or go to Security → Encryption & credentials → Install a certificate → CA certificate.
  3. Tap Install anyway and pick the file in Downloads. Android asks for a screen lock if there is none.
  4. Come back here, the check above turns green.

Android then shows “Network may be monitored”: expected, the device trusts a certificate installed by hand. Chrome honors it, most apps do not.

iPhone, iPad (this device)
  1. Open this page in Safari, tap Download the root certificate, then Allow.
  2. In Settings, tap Profile Downloaded → Install.
  3. Then Settings → General → About → Certificate Trust Settings and turn on the root certificate. Without this step the certificate is installed but not trusted.
  4. Come back here, the check above turns green.
Computer (this device)

On the computer running the dev server, npx @jsenv/https-local init installs and trusts the root certificate.

On another computer, download it and add it to the trusted root certificates of the system. On macOS: open the file, then set it to “Always Trust” in Keychain Access.

Good to know

The device trusts anything signed by this root certificate. Its key never leaves the computer running the dev server, only the certificate is served: the trade-off already made on that computer.

See the fingerprint, or remove it. Android: Settings → Encryption & credentials → Trusted credentials → User → tap it. iPhone, iPad: Settings → General → VPN & Device Management → the profile.
