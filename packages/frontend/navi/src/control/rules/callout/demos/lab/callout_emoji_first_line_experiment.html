Callout — emoji on the first line

The issue

The icon and close button use height: 1lh — the CSS line-height property value. Without emoji that matches the rendered line exactly. But an emoji glyph is taller than normal text, which makes the browser inflate the rendered line-box height beyond 1lh. The dotted border shows the real height of the text element: notice how it grows with the emoji, while the icon/close button stay the same size and appear misaligned.

Option A — explicit line-height on the message

Setting a fixed line-height (e.g. 1.5) on the message element forces every line box to that height regardless of content. Emoji can no longer inflate the line. The dotted border should now be the same height with or without the emoji, matching 1lh on the icon/close button.

Trade-off: the fixed line-height is applied even when there is no emoji, so every line is slightly taller than the browser default. The comparison row below shows this cost.

Option B — phantom text + align-items: baseline

An invisible <span>A</span> inside the icon and the close button gives each a real text baseline. With align-items: baseline on the row, all items align on that shared baseline. Crucially, emoji does not change the text baseline (only the leading above it), so alignment stays correct. The icon height is 1cap (cap-height) so it appears visually centered on the text line.

Option C — text-box: trim-both cap alphabetic

Trims the half-leading above and below text to the cap-height / alphabetic baseline. The emoji's extra height spills outside the text box but has no layout effect — the box stays the height of the text glyphs. The dotted border should be identical with and without the emoji. Chrome 123+ only, not yet in Firefox / Safari.
